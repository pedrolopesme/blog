---
title: "O Mito do Dev 10x"
summary: "Software é construção coletiva; medir produtividade individual com uma métrica única é o que sustenta o mito."
categories: ["Carreira", "Ofício"]
---

O mito do dev 10x persiste.

 E, como todo bom mito, é uma mistura de verdade, exagero e contos de fadas.

Não vou negar o óbvio: existem devs mais produtivos que outros.

O problema começa com as métricas de produtividade individual. Spoiler: em geral, são ruins.

Software não é um produto individual, é uma construção coletiva.

Como se mede produtividade? A implicação de que existe uma métrica única e absoluta para rankear devs é absurda.

O que está sendo construído? Qual tecnologia usa? Qual o contexto do projeto? Qual a prioridade do negócio? As variáveis são infinitas.

Saber cortar features desnecessárias é sempre mais valioso do que escrever mil linhas de código.

Além disso, nunca conheci ninguém que fosse 10x melhor em qualquer situação.

E mesmo que existisse, isso não importa.  Quem entrega software é o time, não um indivíduo.

Um dev 10x não é aquele que digita como se estivesse em um filme de ficção científica. É aquele que resolve problemas de forma inteligente, sem criar novos problemas no processo.

Tempo de escrita de código é tão relevante quanto o resto do ciclo de vida do software.

Se o dev é o “herói” de um serviço ou componente, ele vira um ponto único de falha. E isso é uma bomba-relógio.

Pode fazer sentido no início de uma startup, quando a prioridade é chegar vivo no próximo mês. Mas, à medida que a empresa cresce, a propriedade do software precisa ser do time.

Pessoas saem de férias, ficam doentes, pedem demissão. O time precisa sobreviver a isso.

Se times são os donos do software, o papel de um líder técnico não é caçar devs 10x. É criar times de alto desempenho. É isso que deveria ser multiplicado por 10.

Qualquer um consegue montar um time de devs “ex-empresa unicórnio” ou ex-alunos de alguma faculdade famosa.

O problema é que a empresa vai precisar escalar sua operação. Nesse momento, é imperativo ter múltiplos times excelentes.

O real desafio está em criar um ambiente onde "devs 1x” conseguem entregar resultados consistentes, rápidos e impactantes para o negócio.

O foco deve ser criar processos que permitam que todos somem esforços e entreguem valor para o negócio.

No fim, os melhores times de desenvolvimento são aqueles onde devs comuns entregam  resultados excepcionais.

Isso sim deve ser multiplicado por 10.
